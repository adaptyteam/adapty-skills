# Maintainer notes: `flow-audit`

Evidence and history behind the rules in `CLAUDE.md`: measurements, test rounds, dated findings. Not loaded into sessions. Read the part you need before changing a rule; add new findings here, never to `CLAUDE.md`.

## Files

- `plugin/skills/flow-audit/SKILL.md` — the audit skill's entry point. Five phases (resolve/authenticate → select the flow → fetch config + catalog + every placement → run `verify-config.py`, `audit-flow.py --report`, `flows config validate`, in that order → report), read-only throughout, and a verdict rule that never certifies what it could not see: **Ready to publish** only when zero blockers fired **and** every open `question` has been put to the user, otherwise **Almost ready: n things I could not check**. The script's report is the **content and order** of the answer, not its wording: the agent relays it in the user's language, keeping every numbered finding, and the skill carries a short example of its shape. The report ends in **What happens next** (routes every numbered finding by who acts — answer first, "I can fix …", yours in the dashboard, optional — pointing back at numbers, never restating a finding) and **Check these yourself** (each line says where to look). Placements are read, not assumed: `placements get` audiences carry `flow_id`, so the audit says which placement shows the flow, or raises `no-placement` / `placement-inactive` as risks. The **advisory store-review dimension** (six checks, `risk`/`question` only) prints in its own section with a fixed disclaimer: **it never changes the verdict**, not even the "Almost ready" downgrade an ordinary question causes. See finding 27.
- `plugin/skills/flow-audit/references/audit-flow.py` — the six-family completeness checker (stdlib only): triggers, store compliance, products, variables, localization, placeholders, plus the placement check. Takes the bare config plus the catalog JSON and, optionally, `--placements` (an array of `placements get` bodies); `--report` prints the user-facing block, `--json` prints raw findings, no flag prints a plain list. Every finding's `message`/`fix` is written for the person reading the report — builder labels, screen captions, one line of why — so **nothing may parse message text**: the dead-affordance merge reads the element's text from the config, and tests key on check names. Exit 0 no blockers, 1 at least one blocker, 2 usage/unreadable input.
- `plugin/skills/flow-audit/references/checks.md` — per-check evidence: what each check looks at, its severity and why, its calibration result against the tracked fixture corpus and real flows, and the false-positive/false-negative trap it closed. Read before changing a check. It stays the owner of every **completeness** check and carries a pointer, not a copy, for the store-review six.
- `plugin/skills/flow-audit/references/store-review.md` — the same contract for the six advisory store-review checks (`trial-toggle`, `billed-amount-not-shown`, `derived-price-louder`, `no-period-disclosed`, `trial-terms-incomplete`, `external-purchase-link`). Owns the two customer rejection notices **verbatim with their dates**, the four evidence tiers, the framing rule and why it is a rule, per-check calibration in both directions plus each mechanism's negative-test outcome, the two **accepted** false-negative classes, the blind spots (`props.content`-only price reads; type but not colour/position/container; no render), and the ruled-out list — `subscription-under-7-days` above all, so nobody re-adds it from the guideline text. Read before changing one of these six.
